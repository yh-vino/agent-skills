## 附录1 PR 提交规范

- 提交范围：围绕本次接入或维护目标提交相关修改，同步更新受影响的配置、测试和使用说明；无关修改另提 PR。
- 标题与 Commit：简明说明本次接入或维护内容，可使用 feat、fix、test、docs、ci 等前缀；涉及 Bug 修复时写明修复的问题。
- PR 正文：说明修改原因、主要改动及受影响的模型或 Group；有对应 Issue 时附上链接；用简短文字说明做了哪些验证及结果，未执行或失败时如实说明。**PR 中不展示精度和性能数据，也不引用相关报告链接。**
- CI 检查：提交后检查 Quality Gate 和 HCU CI 结果。Fork PR 会跳过 HCU CI，需由维护者将待测提交放到主仓库的可信分支，再手动触发验证。
