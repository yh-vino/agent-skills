# 00 立项

目的：在动手前把“做到什么算完成”定下来。后面所有门禁都以这里的结论为准，验证阶段不能临时改标准。

产出：《优化报告》文档信息、修订记录、第 1 章（1.1 模型简介、1.2 优化背景、1.3 性能目标、1.4 范围与约束）；`state.json` 的 `model` 字段。

## 步骤

1. **收集基本信息**（向用户确认，不猜）：模型名称和版本、模型类别、任务类型（第一版只支持训练）、目标 HCU 型号、对标硬件与卡数、服务客户、上游仓库和接入基线 commit、负责人。
   - 基线 commit 必须能在上游公开仓库查到：`gh api repos/<owner>/<repo>/commits/<sha>`（返回 422 即不存在）。
2. **读上游仓库**，写 1.1 模型简介：出处、参数量、主要结构、输入输出模态、业务场景（3～5 句）。参数量和结构以源码和官方配置为准，不从网上二手资料抄。
3. **找官方训练流程**：官方启动脚本（如 `scripts/*.sh`、`examples/*/run_*.sh`）、数据下载和准备脚本、默认配置。记到 `notes/upstream.md`，后续 README 和“跟随上游”检查都以它为准。
4. **定性能目标**（1.3）：每个指标有目标值、对标基准、验收方式和优先级。拒绝“尽量提升”这类描述；目标来源（客户要求 / 内部立项）写明。
5. **定精度判定标准**（写入 2.4.2 的占位，正式内容在阶段 01 补全）：
   - 分层：算子级（rtol/atol 按 dtype）、训练过程（同 seed 同数据顺序的 loss / grad norm 曲线）、端到端（下游指标）。
   - 优先用“落在竞品多次运行的波动范围内”；端到端训练成本过高时，约定替代方案（训练 N 步、数据子集）及理由。
   - 模板附录 F 目前是待定状态，**不能用其中的参考值当默认值**，必须由用户或项目确认。
6. **定范围与约束**（1.4）：做什么（单机 / 多机、精度格式）、不做什么（推理、改模型结构）、硬性约束（不允许改模型代码、指定框架版本）。
7. 运行 `workspace.py init` 创建工作区，把以上内容写进报告和 `state.json`。

## 门禁

- [ ] 1.3 每个指标都可量化、有验收方式。
- [ ] 精度判定标准已由用户或项目确认，确认人记入 `decisions[]`。
- [ ] 接入基线 commit 可在上游公开仓库查到。

## 常见问题

- 对标硬件只写了“NV”：追问型号和卡数，否则 4.3 的性能比例没有意义。
- 用户还没定精度标准就想开始优化：可以先进阶段 01、02（不依赖精度标准），但阶段 03 的门禁需要它。
