# 05 优化后验证

目的：用完整交付配置确认精度、性能和长时间稳定性都达标。

产出：《优化报告》第 6 章（6.1 正确性与精度、6.2 性能、6.3 稳定性、6.4 推理验证——第一版填“不涉及”）。

## 步骤

1. **冻结交付配置**：所有 `validated` 的 OPT 对应的 Group 都在 recipe 里，配置已重新生成，`turbo-physai optimization check --generated-only <optimization.yaml>` 通过。之后的验证都用这份配置；中途再改代码，就要重新验证受影响的项。
2. **精度（6.1）**：按 2.4.2 的全部层级，比较竞品基线、HCU Baseline、HCU 优化后三组结果，附三条 loss 曲线。`accuracy_only` 的 Group 用 `turbo-physai run --accuracy` 单独验证。判定标准只用阶段 00 确认的那一份。
3. **性能（6.2）**：精度通过后再测。记录 Mean、Median、P95 / P99、Max / Min、吞吐、性能比例、显存峰值。P99 与 Mean 差距大时分析原因（数据加载、周期性 checkpoint、通信波动）。
4. **稳定性（6.3）**：让用户挂长跑（单机八卡建议至少 12 小时，多机建议 24 小时），AI 分析日志：
   - 吞吐随时间的变化，有没有中断、hang、性能衰减；
   - loss 有无漂移或尖刺，grad norm 是否正常，有无 NaN / Inf；FP16 记录 loss scale 和跳过的步数；
   - 通信超时、掉卡、各 rank step 时间差异；
   - 每隔 N 步的显存（allocated / reserved / peak）和进程 RSS，进入稳定阶段后不能持续增长；
   - 断点续训：续训后 loss 平滑衔接，学习率和数据顺序正确，记录 checkpoint 耗时和大小。

   需要在训练脚本里加显存和内存日志时，只加日志、不改训练逻辑，交付前去掉或保持为默认关闭。

## 门禁

- [ ] 6.1 全部精度指标达标。
- [ ] 6.2 达到 1.3 的性能目标（未达到的写明差距和原因，并记入 7.3 遗留问题）。
- [ ] 6.3 长跑、loss / grad、分布式、显存、续训各项无异常。
