# 07 沉淀

目的：让这次适配的成果被下一个模型直接用上——能做成公共件的进公共件，做不成的变成可套用的思路。

产出：《优化报告》第 7 章（7.1 最终优化配置、7.2 收益总览、7.3 遗留问题、7.4 后续计划、7.5 可复用经验）；每个 OPT 的 `reuse` 结论；公共件或思路库的更新提议。

## 步骤

1. **7.1～7.4**：最终配置（镜像、代码 commit、启动命令、配置文件、环境变量与开关，脚本放附录 A）；收益总览（建议配阶梯图，对照 1.3 说明是否达成）；遗留问题（责任方、计划时间）；后续计划（关联未处理的 BOT 编号）。
2. **逐个 OPT 判断复用方式**，写进 `state.json` 的 `reuse` 和 7.5：

   | 结论 | 判断条件 | 后续动作 |
   |---|---|---|
   | `common` | 已经放在 `optimizations/common/` 或 `operators/` | 确认其他已适配模型能否启用（在它们的 recipe 里 `extends`） |
   | `common-candidate` | 同时满足：① 目标是框架或库入口（torch、transformers、diffusers、deepspeed、mmcv、mmdet、mmdet3d 等），不是模型仓库自己的代码；② 实现不读取模型特有的属性、配置、数据字段，也不对 shape 做只有该模型满足的假设；③ 对该入口的任何调用方行为等价，不改变训练 recipe | 提议迁入 `common/<framework>/`：不收集目标哈希（`collect_target_hash=False`），用 `runtime_condition` / `compatibility_check` 保证安全，补公共件单测；另一个模型已替换过同一入口时优先做 |
   | `pattern` | 目标是模型自己的代码，但手法可以套用到其他模型 | 在 `patterns/` 对应类别下补充本案例（路径、前提、坑），新手法就新增条目 |
   | `model-only` | 只对本模型成立 | 7.5 写一句原因 |

3. **写 7.5 可复用经验**：抽象成与具体模型无关的结论，标注适用的模型类别（自动驾驶 / VLA / 世界模型 / 视觉训练推理）。
4. **把 5.9 未采纳的尝试也整理进来**：失败原因同样能帮下一个模型少走弯路，相关类别的 `patterns/` 条目里记一笔“试过但无效”及条件。
5. 公共件迁移和思路库更新各自单独提 PR，不混进本模型的 PR。

## 门禁

- [ ] 每个 `delivered` 的 OPT 都有 `reuse` 结论。
- [ ] `common-candidate` 和 `pattern` 的后续动作已告知用户，由用户决定是否立项。
